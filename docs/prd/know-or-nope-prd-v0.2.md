### 0.2 v0.1 대비 변경 요약

1. **[확정]** 사용자를 **교사(콘텐츠 생산자)**와 **학생(학습자)**로 명확히 분리하고, 수업용·지속 운영을 전제로 변경.
2. **[확정]** 과목을 국어에 한정하지 않고, **과목/분야 → 단어장 → 시작 전 설정 → 학습 → 결과** 구조로 변경.
3. **[확정]** 학습 범위·순서·최초 표시 영역 설정은 **학습 화면이 아니라 진입 전 화면**에 배치.
4. **[확정]** 단어·설명·그림을 **계속 추가·수정**할 수 있는 비개발자 친화적 운영 흐름을 도입.
5. **[확정]** 이미지 제작의 최우선 가치는 **생산성**. 단어별 수동 검색·개별 프롬프트 작성을 기본 운영 방식으로 채택하지 않음.
6. **[제안]** 이미지의 자동 수집/생성 → 후보 연결 → 교사 일괄 검수 → 공개 흐름을 도입.
7. **[제안]** 학생 개인의 진행·평가 결과는 별도 로그인 없이 브라우저 로컬에 저장.
8. **[미결정]** 교사용 편집 도구를 웹 CMS로 제공할지, 스프레드시트와 별도 검수 화면으로 제공할지 결정하지 않음.

## 1. 제품 개요

### 1.1 한 줄 정의

**교사가 수업용 개념 카드를 쉽게 만들고 갱신하면, 학생이 단어·그림·설명을 선택적으로 가리며 학습하고 스스로 이해도를 확인하는 웹서비스.**

### 1.2 해결할 문제

- **교사:** 수업용 단어장을 자주 갱신해야 하지만 개발 도구나 저장소를 직접 다루기는 어려움.
- **교사:** 단어 수만큼 시각 자료를 찾고 제작하는 작업이 반복적이고 시간이 많이 듦.
- **학생:** 단어장 진입 이후 복잡한 설정 없이 카드 학습에 집중하고, 알고 있는 개념과 모르는 개념을 구분하고 싶음.
- **개발자:** 콘텐츠가 수정될 때마다 수동 파일 편집·이미지 등록·배포를 반복하는 운영자가 되고 싶지는 않음.

### 1.3 제품 목표

| ID | 목표 | 성공 판정의 방향 |
|---|---|---|
| G-01 | 학생의 즉시 학습 | 로그인 없이 단어장을 선택하고 학습을 시작할 수 있음 |
| G-02 | 과목 독립성 | 국어 외 다른 과목을 코드 수정 없이 콘텐츠로 추가 가능 |
| G-03 | 교사의 자율 운영 | 비개발자 교사가 단어/설명/그림을 등록·수정할 수 있음 |
| G-04 | 이미지 생산 자동화 | 단어를 대량 등록한 뒤 이미지 후보를 일괄 준비할 수 있음 |
| G-05 | 수업 운영 안정성 | 미검수 콘텐츠의 우발적 공개를 차단하고 기존 학습 결과를 최대한 보존 |
| G-06 | 가벼운 학습 기록 | 학생의 자기평가·회차별 결과를 같은 브라우저에서 확인 가능 |

> **제안 운영 지표:** 30개 단어 일괄 등록과 이미지 검수까지 걸리는 시간, 단어당 교사 클릭 수, 이미지 재생성 비율, 공개 오류 건수. 구체적인 목표치는 첫 파일럿 후 정한다.

### 1.4 초기 비목표

- 학생 계정·서버 기반 진도 동기화·교사별 학생 성적 관리
- 정답 입력과 자동 채점, AI 기반 학생 답안 채점
- 완전 자동 무검수 이미지 게시
- 별도 모바일 네이티브 앱 제작
- 원본 레퍼런스의 디자인·콘텐츠를 픽셀 단위로 복제
- 특정 호스팅 서비스·요금제의 선정

| **학생 (학습자)** | 수업 중 또는 자습 | 과목/단어장 선택, 카드 학습, 자기평가, 결과 확인 | 계정 만들기, 앱 설치, 복잡한 초기 설정 |

## 3. 핵심 개념과 정보 구조

### 3.1 콘텐츠 계층

```text
과목/분야 (Subject)        예: 국어, 수학
  └─ 단어장 (Deck)         예: 문학 표현법, 품사, 도형의 기초
       └─ 카드 (Card)      예: 은유법, 의인법, 예각
            ├─ 단어 (Term)
            ├─ 설명 (Definition)
            └─ 그림/시각자료 (Visual, 선택 여부 정책 별도)
```

- **[확정]** 학생은 학습에 앞서 **과목/분야와 단어장을 선택**한다.
- **[확정]** 학습 설정은 단어장 안에 숨겨진 메뉴가 아니라 **시작 전 단계**에서 수행한다.
- **[제안]** 한 단어장은 한 과목에 속하고, 카드는 여러 단어장에 재사용될 수 있다. 카드 ID는 이 경우에도 동일하게 유지한다.
- **[제안]** 단어장 내부의 `단원·주제·난이도·학년`은 카드 선택 필터로 제공할 수 있는 메타데이터다.
- **[미결정]** 과목 목록과 단어장 목록을 별도 화면으로 나눌지, 한 화면에서 2단계 선택할지는 사용량에 따라 결정한다.

### 3.2 전체 정보구조(IA)

```text
[학생 영역]
  S01. 과목 / 단어장 선택
     └─ S02. 학습 전 설정
          ├─ 범위 선택 (전체 / 단원·주제 / 개별 카드)
          ├─ 카드 순서 (무작위 / 가나다순)
          ├─ 초기 표시 설정 (단어 / 그림 / 설명)
          └─ 시작 또는 기존 학습 이어하기
               └─ S03. 카드 학습
                    ├─ 각 영역 개별 가리기/표시
                    ├─ 이전 / 다음
                    └─ 알고 있음 / 모름 / 미판정
                         └─ S04. 결과 / 복습

[교사 영역]
  T01. 단어장 관리
     ├─ 단어장 만들기 / 수정 / 공개 상태 관리
     ├─ T02. 카드 개별 등록·수정
     ├─ T03. 다건 가져오기 (CSV/XLSX 등)
     ├─ T04. 이미지 후보 자동 수집·생성
     └─ T05. 이미지/카드 검수 → 공개
```

### 3.3 카드 UI 핵심 규칙

- 카드는 `단어 / 그림 / 설명`의 세 영역을 기본 모델로 사용한다.
- 세 영역의 표시·숨김은 서로 독립이다.
- 카드 내부의 **개별 표시 토글은 학습 행위**이며, **단어장·범위·순서·기본 표시 프리셋을 바꾸는 설정**과 구분한다.
- 그림이 없는 카드의 표시 정책은 학습을 막지 않고 2영역으로 적응하거나, `그림 없음`을 간결히 안내하도록 한다 **[제안]**.

### 4.1 S01 — 과목 / 단어장 선택

**구성 요소**

- 상단: 서비스 이름과 간단한 안내
- 과목 목록: `국어`, `수학` 등 데이터로 구성; 미등록 과목을 빈 카드로 노출하지 않음
- 선택한 과목의 단어장 목록: 제목, 설명, 카드 개수, 공개 여부에 따른 필터
- 단어장별 `학습 설정으로` 및 진행 기록이 있으면 `이어하기`

**빈 상태:** 공개 단어장이 없는 과목은 안내 문구 표시. 비공개·작성 중 단어장에 학생이 접근할 수 없어야 한다.

### 4.2 S02 — 학습 전 설정

**설정 항목 [P0]**

1. 학습 범위: `전체` / `단원·주제` / `개별 카드`.
2. 정렬: `무작위`(제안 기본값) / `가나다순`.
3. 최초 표시: `단어`, `그림`, `설명`의 개별 공개·가림 프리셋. **제안 기본값:** 단어 가림 / 그림·설명 표시.
4. 선택 카드 개수와 예상 학습 범위 확인.
5. 기존 회차가 있다면 `이어서 학습` / `설정대로 새로 시작` 선택.

**동작 정책**

- 단어장을 바꾸면 해당 단어장의 범위와 설정을 새로 로드한다.
- 같은 단어장에서는 직전 설정을 기본값으로 제안할 수 있다 **[제안]**.
- `시작` 시 학습 대상 ID·순서·프리셋을 회차에 고정한다.
- 학습 중 설정을 바꾸려면 설정 화면으로 돌아가야 하며, 기존 진행에 영향을 주는 변경에는 안내를 표시한다.

### 4.3 S03 — 카드 학습

```text
┌─────────────────────────────────┐
│ ← 단어장          03 / 24        │
│ 판정 완료 10 / 24                │
│ ┌─────────────────────────────┐ │
│ │ 단어            [보이기]     │ │
│ │       ▒▒▒▒▒▒▒▒▒▒▒           │ │
│ ├─────────────────────────────┤ │
│ │ 그림              [가리기]  │ │
│ │       (그림 / 시각자료)      │ │
│ ├─────────────────────────────┤ │
│ │ 설명              [가리기]  │ │
│ │       개념을 설명하는 문장   │ │
│ └─────────────────────────────┘ │
│ [모름] [판정 취소] [알고 있음]   │
│ [이전]                    [다음]│
└─────────────────────────────────┘
```

**동작 정책 [제안/P0]**

- 개별 영역의 공개·가림은 해당 카드에만 임시 적용한다. 다른 카드로 이동하면 학습 전 설정의 프리셋을 재적용한다.
- 평가 버튼은 해당 카드의 현재 선택 상태를 분명히 표시한다. `모름`에서 `알고 있음`으로 변경하면 이전 값을 덮어쓴다.
- 평가하지 않고 이동해도 `미판정`으로 유지한다.
- `나가기`는 학습 중단이 아니라 진행 상태 보존이다. 사용자가 명시적으로 새 회차를 시작해야 기존 진행 회차가 교체된다.
- 모든 영역이 가려지지 않도록 하는 정책은 시작 설정뿐 아니라 카드 조작에도 동일하게 적용할지 **미결정**.

### 4.4 S04 — 결과

**집계식**

- `N = known + unknown + unrated`
- `판정률 = (known + unknown) / N`
- `알고 있는 비율 = known / (known + unknown)`
- 판정 0개일 때 알고 있는 비율은 `—`로 표시한다.

**화면 요소**

- 전체 카드 및 세 평가 상태별 개수
- 카드별 판정 목록, 카드 다시 보기
- `완료` 시 회차 이력 저장
- `모르는 카드 재학습`은 P1. P0에서는 새 회차 시작으로 돌아갈 수 있다.

## 6. 이미지 생산·등록 파이프라인

### 6.1 목표

**[확정] 교사가 단어별로 이미지 검색어나 프롬프트를 반복 입력하지 않아도, 여러 단어에 대해 시각자료 후보를 한 번에 준비할 수 있어야 한다.**

이 기능은 부가 장식이 아니라 **교사용 제작 생산성의 핵심 기능**으로 간주한다.

### 6.2 이미지 공급 전략

| 방법 | 적합한 콘텐츠 | 장점 | 주의 사항 |
|---|---|---|---|
| 검색 기반 수집 | 사물·장소·실제 행동·실물 사진 | 빠르고 기존 이미지 활용 | 검색 적합성, 출처·라이선스·재배포 권한 확인 |
| AI 일괄 생성 | 은유·반어·의인 등 상황을 시각화한 개념 | 맞춤형 장면, 일관된 스타일 | 개념 왜곡·문자 오류·비용·재생성 |
| 규칙 기반 도식/SVG | 문장 구조·품사·관계·기초 도형 | 텍스트 정확성, 재사용·저비용 | 표현 가능한 유형이 제한적 |
| 직접 업로드 | 교사 보유 이미지·직접 제작 도식 | 품질과 의도를 직접 통제 | 수작업 부담 |

**[제안]** 초기 버전에서는 공급원을 모두 구현하지 않아도 된다. `검색 기반 1종 + AI 생성 1종 + 직접 업로드` 중에서 실제 품질·처리 속도·비용을 검증하여 최소 1개의 자동 생산 경로를 P0로 선정한다. 다중 공급원 자동 라우팅은 P1로 둘 수 있다.

- 입력: `과목`, `학년/난이도(선택)`, `단어`, `설명`, `시각화 유형(자동/실사/삽화/도식)`.
- 시스템은 입력값을 바탕으로 검색 질의 또는 이미지 생성 프롬프트를 자동 구성한다.
- 교사가 매번 자유문 프롬프트를 직접 작성해야만 다음 단계로 진행할 수 있게 하지 않는다.
- 검색 이미지 후보에는 원본 URL·출처·라이선스·저작자 표기 정보를 연결한다.
- AI 이미지 후보에는 생성 제공자·모델·생성 시점·내부 사용 기록을 연결한다.
- 한국어 문법 도식처럼 정확한 글자가 중요한 경우, 텍스트를 이미지 생성 모델에게 그리게 하지 않고 별도 텍스트/SVG 렌더링을 우선 검토한다.

- 무단 스크래핑을 기본 전략으로 정의하지 않는다. 공급원별 약관·검색 API 이용 조건을 지킨다.

- 이미지 생성·검색의 실패, 작업 시간 초과, 사용량 한도 도달 시 기존 승인 콘텐츠는 그대로 유지한다.

## 7. 콘텐츠 상태와 게시 정책

### 7.1 권장 상태 모델 [제안]

```text
작성 중(draft)
   ↓ 내용 기본 검증 완료
검수 대기(in_review)
   ├─ 수정 필요 → 작성 중
   └─ 승인 → 공개(published)
                  └─ 수정 발생 → 변경 초안(draft_revision)
                                   └─ 재검수 → 새 공개 버전
```

- `published` 콘텐츠만 학생용 목록에 노출한다.
- 이미 공개된 카드의 변경을 편집 중일 때는 학생에게 **마지막 승인 버전**을 계속 제공하는 것을 기본 원칙으로 한다.
- 이미지가 필수라는 정책이 결정된다면 해당 이미지가 미승인인 카드는 공개 불가다.
- 그림이 선택 항목이라는 정책이면 `그림 없음`도 교사가 명시적으로 확정할 수 있다.
- 카드 ID는 제목·정렬·분류가 바뀌어도 변경하지 않는다.

### 7.2 미결정 정책

- 그림을 **반드시 한 개 이상** 갖춰야 공개할 수 있는가? 현재는 선택 항목으로 제안.
- 카드별 이미지 여러 개를 저장하되 학습에는 하나만 표시할 것인가?
- 다건 가져오기에서 같은 과목/단어장/단어를 중복으로 입력했을 때의 기본 처리 방식은 무엇인가?
- 편집 완료와 공개 승인을 같은 교사가 수행하는가? (초기에는 동일인 가정)
- 단어장 공개 전 전체 카드 검수를 필수로 할 것인가? (최소 공개 카드 단위 검수 필요)

```json
  "cards": [
    {
      "id": "card-kor-001",
      "revision": 1,
      "term": "의인법",
      "definition": "사람이 아닌 대상을 사람처럼 표현하는 방법",
      "units": ["표현법"],
      "visual": {
        "type": "image",
        "src": "assets/images/card-kor-001.webp",
        "alt": "나무가 사람처럼 손을 흔드는 삽화",
        "attribution": "자체 제작 이미지"
      }
    }
  ]
}
```

**필드 규칙**

- `subject.id`, `deck.id`, `card.id`는 안정적인 식별자이며 표시 이름에서 즉석 생성하지 않는다.
- `term`, `definition`은 필수. `visual`은 현재 제안상 선택 사항.
- `card.revision`은 정의·이미지·학습 의미에 영향을 주는 변경 시 증가시키는 방향을 권장한다.
- `deck.cardIds`에 동일 카드 ID가 중복되더라도 학습 대상은 한 번만 포함한다.
- 공개 출력에는 초안·미검수 자산, 관리 전용 메모, 비밀키를 포함하지 않는다.
- 이미지는 파일명·경로와 자산 메타데이터를 카드 ID에 안정적으로 연결한다.

### 8.2 교사용 관리 데이터(추가 개념)

| 객체 | 주요 데이터 | 목적 |
|---|---|---|
| CardDraft | 단어, 설명, 과목/단어장, 상태, 수정시각 | 원본 콘텐츠 관리 |
| ImageCandidate | 카드 ID, 후보 URI, 유형, 처리 상태, 출처·라이선스 또는 생성 정보 | 다건 이미지 후보 관리 |
| ApprovedAsset | 승인된 후보 ID, 실제 자산 경로, 대체 텍스트, 승인시각 | 학생용 이미지 연결 |
| Publication | 공개 버전, 포함 카드 ID, 공개시각, 콘텐츠 검사 결과 | 수업용 공개 데이터의 기준 |

**로컬 저장 정책 [제안/P0]**

- 단어장별 학습 중 상태와 완료 회차 이력을 구분한다.
- 판정 변경·카드 이동 시 저장하고, 저장 불가 시 명시적으로 경고한다.
- 로컬 데이터는 브라우저·기기별로 분리되며 계정 동기화를 제공하지 않는다.
- 콘텐츠 수정으로 카드가 사라지거나 의미가 변경된 경우 안전하게 복구·안내한다. 과거 완료 기록을 현재 내용 기준으로 소급 수정하지 않는다.
- 지나치게 많은 로컬 이력이 쌓이지 않도록 보관 개수 제한 또는 백업 정책은 구현 시 결정한다.

### 9.1 학생 학습

| ID | 시나리오 | 기대 결과 |

## 11. 단계별 범위 및 릴리스 기준

### Phase A — 수업 투입 가능한 학습 MVP (P0)

- [ ] 과목/단어장 선택 → 시작 전 설정 → 학습 → 결과의 일관된 UX
- [ ] 단어·그림·설명 카드, 영역 독립 토글, 이전/다음, 자기 평가
- [ ] 단어장별 LocalStorage 이어하기·완료 이력
- [ ] 공개 콘텐츠 구조와 데이터 검증
- [ ] 교사가 단어·설명을 다건 등록할 수 있는 편집 흐름(임시 운영 절차 포함 가능)
- [ ] 이미지 대량 준비의 최소 자동 경로 1개와 교사 검수
- [ ] 공개/비공개 및 미검수 이미지 노출 차단
- [ ] 모바일 주요 화면 및 오류 처리 검증

**Phase A 운영 허용 조건:** 첫 수업을 위한 1회성 개발자 보조 게시 작업은 가능하나, 이를 영구적인 콘텐츠 운영 방식으로 간주하지 않는다.

### Phase B — 교사 자율 운영 (P0 완결 및 P1 일부)

- [ ] 교사가 개발자 개입 없이 콘텐츠 수정·게시 수행
- [ ] 다건 등록·중복 처리·이미지 실패 재시도 최적화
- [ ] 이미지 후보 검색/생성 품질과 작업량 개선
- [ ] 교사용 공개 전 미리보기·변경 내역 제공
- [ ] 모르는 카드 재학습, 이력 백업·복원

### Phase C — 필요할 때만 검토 (P2)

- [ ] 학생별 계정·기기 간 동기화
- [ ] 교사용 학생 학습 분석 대시보드
- [ ] 복수 교사 공동 편집·승인 체계
- [ ] 자동 문제 출제·주관식 채점·학습 추천
- [ ] 고급 이미지 추천 엔진 및 자체 시각화 템플릿 라이브러리

## 12. 남은 의사결정 사항 (우선순위순)

| 우선 | 질문 | 현재 제안 | 결정이 필요한 이유 |
|---|---|---|---|
| 1 | 교사가 콘텐츠를 어디서 편집하는가? | 스프레드시트 기반 대량 입력 또는 비개발자 CMS 검증 후 선택 | 운영 UI/권한·동기화 방식 결정 |
| 2 | 교사의 등록 패턴은? | 초기 대량 등록 + 이후 소량 추가를 우선 가정 | 대량 가져오기 vs 단건 편집 UX 비중 |
| 3 | 최초 단어장은 어떤 과목·단원인가? | 국어 샘플 단어장부터 시작 | 실제 콘텐츠 검증과 분류 체계 확정 |
| 4 | 그림이 없는 카드도 공개 가능한가? | 가능, 2영역 카드로 표시 | 이미지 생산 실패가 수업 일정을 막을지 결정 |
| 5 | 그림의 우선 표현 방식은? | 개념에 따라 실사/삽화/도식 혼합 | 이미지 공급원 및 품질 기준 결정 |
| 6 | 최초 자동 이미지 공급원은? | 검색 또는 AI 생성 중 소량 샘플로 품질/처리시간/비용 평가 | 이미지 파이프라인 구현 범위 |
| 7 | 교사 이미지 검수 수준은? | 후보 검수 후 일괄 승인, 예외만 개별 교체 | 생산성·정확성 균형 |
| 8 | 콘텐츠 배포 전 승인 주체는? | 초기는 교사 1인 승인 | 관리 권한과 공개 상태 모델 결정 |
| 9 | 학생의 학습 범위 설정 기본값은? | 전체 카드·무작위·단어 가림 | 실제 수업 운영 UX에 영향 |
| 10 | 카드 내용 변경 시 진행 중 회차 처리 기준은? | 카드 ID·콘텐츠 버전 확인 후 안전 안내 | 기록 왜곡·학습 중단 방지 |

**지금 가장 먼저 준비할 실제 자료 [제안]:** 국어 단어 20~30개(단어·설명·단원/주제), 그중 시각화가 쉬운 단어와 어려운 단어를 섞은 이미지 후보 검수용 샘플. 이 자료로 제작 플로우의 실제 작업량을 먼저 측정한다.

## 13. 레퍼런스와 신규 설계의 구분

### 13.1 레퍼런스에서 확인된 핵심 개념

- 용어/그림/정의의 3개 정보 영역
- 각 영역 개별 숨김/표시
- 카드 선택과 순서 설정(무작위·알파벳순)
- Self-check 형태의 이해도 표시
- 선택 카드 세트 공유 기능

### 13.2 신규 제품을 위해 별도로 설계한 부분

- 과목·단어장 선택을 학습 설정 앞단으로 분리한 UX
- **교사용** 콘텐츠 추가·수정·이미지 관리·공개 기능
- 단어별 검색·AI 생성·도식 템플릿 등 이미지 대량 생산 흐름
- `알고 있음 / 모름 / 미판정`의 명시적인 3상태 평가
- 단어장별 로컬 학습 이력·회차 결과
- 콘텐츠 버전 및 미검수 이미지 공개 제어

> 원본의 Self-check 세부 동작, 각 영역의 카드 이동 시 가림 상태 유지 방식, 로컬 저장 여부 등은 원본 화면에서 모든 경우의 수를 실제 클릭으로 확인한 사항이 아니다. 본 문서에 기재된 그 부분의 동작은 **우리 앱에 적용할 제안 규칙**이지 원본과 완벽히 동일하다는 주장이 아니다.
